# 10 — Internationalisation (i18n)

**Languages: English (EN), Portuguese (PT), German (DE)**

Multilingual support is a core deliverable of the Starter Package, not a
future phase. The studio serves an Algarve market where EN, PT, and DE are
the three dominant languages of the client base — local Portuguese residents,
British and Irish expats, and German tourists.

---

## Approach — route-based locale with cookie persistence

Each language gets its own URL prefix. This is the only approach that gives
proper SEO value (hreflang, indexed pages per locale) and clean analytics
(sessions segmented by language path).

| Locale | Route prefix | Example |
|---|---|---|
| English (default) | `/` | `auratattoo.pt/` |
| Portuguese | `/pt` | `auratattoo.pt/pt` |
| German | `/de` | `auratattoo.pt/de` |

When a user selects a language, two things happen simultaneously:
1. The browser navigates to the locale-prefixed route
2. A `NEXT_LOCALE` cookie is set to persist the preference across sessions

On subsequent visits, middleware reads the cookie and redirects before the
page renders. If no cookie exists, middleware checks `Accept-Language` headers
and falls back to English.

This cookie is classified as **strictly necessary / functional** under the
ePrivacy Directive. It stores a user interface preference, not tracking data.
It does not require cookie consent.

`app/[locale]/`. All routes automatically gain locale awareness.

## Locale type and constants

Create `app/lib/locale.ts`:

```ts
export const LOCALES = ['en', 'pt', 'de'] as const
export type Locale = typeof LOCALES[number]
export const DEFAULT_LOCALE: Locale = 'en'
export const LOCALE_COOKIE = 'NEXT_LOCALE'
export const LOCALE_COOKIE_MAX_AGE = 60 * 60 * 24 * 365  // 1 year

export const LOCALE_LABELS: Record<Locale, string> = {
  en: 'English',
  pt: 'Português',
  de: 'Deutsch',
}

export const LOCALE_SHORT: Record<Locale, string> = {
  en: 'EN',
  pt: 'PT',
  de: 'DE',
}

export function isValidLocale(value: unknown): value is Locale {
  return LOCALES.includes(value as Locale)
}

// Maps browser Accept-Language codes to supported locales
export function resolveLocaleFromHeader(acceptLanguage: string): Locale {
  const preferred = acceptLanguage.split(',').map(l => l.split(';')[0].trim().toLowerCase())
  for (const lang of preferred) {
    if (lang.startsWith('pt')) return 'pt'
    if (lang.startsWith('de')) return 'de'
    if (lang.startsWith('en')) return 'en'
  }
  return DEFAULT_LOCALE
}
```

## Middleware

Create `middleware.ts` at the project root:

```ts
import { NextRequest, NextResponse } from 'next/server'
import { LOCALES, DEFAULT_LOCALE, LOCALE_COOKIE, resolveLocaleFromHeader, isValidLocale } from './app/lib/locale'

const PUBLIC_FILE = /\.(.*)$/

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl

  // Skip static files, API routes, and Next.js internals
  if (
    pathname.startsWith('/_next') ||
    pathname.startsWith('/api') ||
    pathname.startsWith('/favicon') ||
    PUBLIC_FILE.test(pathname)
  ) {
    return NextResponse.next()
  }

  // Check if pathname already has a locale prefix
  const pathnameLocale = LOCALES.find(
    locale => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`
  )

  if (pathnameLocale) {
    // Already on a locale route — set/refresh cookie to match
    const response = NextResponse.next()
    response.cookies.set(LOCALE_COOKIE, pathnameLocale, {
      maxAge: 60 * 60 * 24 * 365,
      sameSite: 'lax',
      secure: process.env.NODE_ENV === 'production',
      path: '/',
    })
    return response
  }

  // No locale prefix — determine preferred locale
  const cookieLocale = request.cookies.get(LOCALE_COOKIE)?.value
  const locale = isValidLocale(cookieLocale)
    ? cookieLocale
    : resolveLocaleFromHeader(request.headers.get('accept-language') ?? '')

  // English is the root — no redirect needed
  if (locale === DEFAULT_LOCALE) {
    return NextResponse.next()
  }

  // Redirect to locale-prefixed route
  const url = request.nextUrl.clone()
  url.pathname = `/${locale}${pathname}`
  return NextResponse.redirect(url)
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
}
```

## Content system

import { en } from './en'
import { pt } from './pt'
import { de } from './de'
import type { Locale } from '@/app/lib/locale'

export type ContentSchema = typeof en

const CONTENT_MAP = { en, pt, de } as const

export function getContent(locale: Locale): ContentSchema {
  return CONTENT_MAP[locale]
}

### `app/content/en.ts`

Rename the existing `export const en = { ... }` — no structural changes needed.
The English file is the source of truth. All keys in `pt.ts` and `de.ts` must
exactly match the structure of `en.ts`. TypeScript will enforce this via the
`ContentSchema` type.

### `app/content/pt.ts`

Create with the full Portuguese translation. Every string in `en.ts` must have
a corresponding Portuguese string. Structure is identical — only string values
change.

Key translations to verify with a native speaker before launch:
- Booking form field labels and error messages
- FAQ answers (legal language around deposits and cancellation)
- Email template body copy in the `emailTemplates` block
- Pricing notes (payment method names: "Multibanco" stays as-is)

### `app/content/de.ts`

Create with the full German translation. Key considerations:
- German uses formal "Sie" rather than informal "du" in business contexts —
  use "Sie" throughout for all client-facing copy
- Legal/deposit copy must be accurate for German-speaking clients
- Phone prefix defaults to `+351` (studio is in Portugal) — this is correct
  regardless of client language

## App router — locale layout

Rename `app/layout.tsx` → `app/[locale]/layout.tsx`:

```tsx
import { cookies } from 'next/headers'
import { type Locale, LOCALES, DEFAULT_LOCALE, isValidLocale } from '@/app/lib/locale'

export async function generateStaticParams() {
  return LOCALES.map(locale => ({ locale }))
}

export default async function LocaleLayout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ locale: string }>   // Next.js 15 — params is a Promise
}) {
  const { locale: localeParam } = await params
  const locale: Locale = isValidLocale(localeParam) ? localeParam : DEFAULT_LOCALE

  return (
    <html
      lang={locale}
      className="..."
    >
      <body ...>
        {children}
      </body>
    </html>
  )
}
```

Note: In Next.js 15, `params` in layouts and pages is a `Promise` and must
be `await`-ed. This is a breaking change from Next.js 14.

      <main>
        <Hero content={content.hero} whatsapp={content.whatsapp} />

content slice as a prop. This is the only architectural change to existing
components — no logic changes, only prop threading.

## Language switcher in Nav

The existing cosmetic `EN` button is replaced with a functional
`LanguageSwitcher` client component:

```tsx
// app/components/shared/LanguageSwitcher.tsx
'use client'

import { useRouter, usePathname } from 'next/navigation'
import { LOCALES, LOCALE_SHORT, LOCALE_COOKIE, type Locale } from '@/app/lib/locale'

export function LanguageSwitcher({ currentLocale }: { currentLocale: Locale }) {
  const router = useRouter()
  const pathname = usePathname()

  function switchLocale(next: Locale) {
    // Remove current locale prefix from pathname
    const stripped = LOCALES.reduce(
      (p, loc) => p.replace(new RegExp(`^/${loc}`), ''),
      pathname
    ) || '/'

    // Set cookie via document (client-side, SameSite=Lax safe)
    document.cookie = `${LOCALE_COOKIE}=${next};max-age=${60 * 60 * 24 * 365};path=/;samesite=lax`

    // Navigate to new locale route
    router.push(next === 'en' ? stripped : `/${next}${stripped}`)
  }

  return (
    <div className="hidden md:flex items-center gap-0.5 border border-sage/40 rounded-md overflow-hidden">
      {LOCALES.map(locale => (
        <button
          key={locale}
          type="button"
          onClick={() => switchLocale(locale)}
          aria-pressed={currentLocale === locale}
          aria-label={`Switch to ${locale.toUpperCase()}`}
          className={[
            'px-2.5 py-1 text-xs font-medium transition-colors',
            currentLocale === locale
              ? 'bg-terracotta text-white'
              : 'text-olive hover:text-ink hover:bg-blush/60',
          ].join(' ')}
        >
          {LOCALE_SHORT[locale]}
        </button>
      ))}
    </div>
  )
}
```

Pass `currentLocale` to the Nav component from the page so it can render the
switcher with the correct active state.

## Metadata per locale

In `app/[locale]/page.tsx`, export `generateMetadata`:

```ts
export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: string }>
}): Promise<Metadata> {
  const { locale: localeParam } = await params
  const locale: Locale = isValidLocale(localeParam) ? localeParam : DEFAULT_LOCALE
  const content = getContent(locale)
  const baseUrl = process.env.NEXT_PUBLIC_BASE_URL ?? ''

  return {
    title: content.meta.title,
    description: content.meta.description,
    alternates: {
      canonical: locale === 'en' ? baseUrl : `${baseUrl}/${locale}`,
      languages: {
        'en': baseUrl,
        'pt': `${baseUrl}/pt`,
        'de': `${baseUrl}/de`,
        'x-default': baseUrl,
      },
    },
    openGraph: {
      title: content.meta.title,
      description: content.meta.description,
      locale: locale === 'en' ? 'en_GB' : locale === 'pt' ? 'pt_PT' : 'de_DE',
      alternateLocale: locale !== 'en' ? ['en_GB'] : ['pt_PT', 'de_DE'],
    },
  }
}
```

The `x-default` hreflang points to the English root. All three locale URLs
must exist and return 200 for hreflang to be valid.

## Cookie — GDPR classification

| Cookie | Name | Purpose | Classification | Consent required | Max age |
|---|---|---|---|---|---|
| Language preference | `NEXT_LOCALE` | Stores user's language choice across sessions | Strictly necessary / Functional | No | 1 year |
| Cookie consent record | `COOKIE_CONSENT` | Records what the user chose in the consent banner | Strictly necessary | No | 1 year |
| Google Analytics | `_ga`, `_ga_*` | User behaviour analytics | Analytics | **Yes** | 2 years |

The language cookie must be documented in the Cookie Policy (`/legal/cookies`)
even though it requires no consent. It should be listed under "Functional
cookies — always active."

## Sitemap update for i18n

`app/sitemap.ts` must include all three locale variants:

```ts
export default function sitemap(): MetadataRoute.Sitemap {
  const base = process.env.NEXT_PUBLIC_BASE_URL ?? ''
  const locales = ['', '/pt', '/de']  // '' = English root

  const pages = ['', '/legal/terms', '/legal/privacy', '/legal/refunds']

  return locales.flatMap(locale =>
    pages.map(page => ({
      url: `${base}${locale}${page}`,
      lastModified: new Date(),
      changeFrequency: page === '' ? 'monthly' : 'yearly',
      priority: page === '' ? 1 : 0.3,
    }))
  )
}
```

## Translation quality notes

- All three language files must be reviewed by a native speaker before launch
- Do not use machine translation for client-facing copy without human review
- The `de.ts` file is especially important — German-speaking clients will
  notice poor translation quality more than most
- FAQ answers about the deposit policy and cancellation terms must be legally
  accurate in all three languages
- Use formal register (vous/Sie/o senhor) for all client-facing copy
